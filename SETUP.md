# Оригинальный Look + бот

Ветка `codex/look-original-backend` основана на оригинальном `look-main`.
Основной интерфейс, шторки и анимации взяты из исходного приложения.
Prisma заменена серверным доступом к Supabase REST; каталог — TVmaze, как у бота.

## Локальный предпросмотр

`pnpm install --frozen-lockfile`, затем `pnpm dev`.
Открыть http://localhost:3000.

Без настроек Supabase в development используются два демонстрационных сериала
с сокращённым набором эпизодов и без постеров. Отметки сохраняются в
`.local-data/1.json`; эта папка не попадает в Git. Это НЕ боевой аккаунт Telegram.
Docker, PostgreSQL и Prisma для предпросмотра не нужны.

## Подключение к настоящему боту

1. Выполнить `supabase/look-progress.sql` в том же проекте Supabase, где бот
   хранит таблицу `subscriptions`. Скрипт добавляет две отдельные таблицы;
   существующие подписки и курсор уведомлений не изменяет.
2. Задать только на сервере `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
   `TELEGRAM_BOT_TOKEN` (токен именно того бота, который открывает миниапп).
   Рекомендуется также отдельный случайный `SESSION_SECRET`.
   Не использовать префикс NEXT_PUBLIC для этих ключей и не коммитить `.env.local`.
3. Собрать `pnpm build`, развернуть по HTTPS и установить URL в кнопке
   web_app/меню бота. Вход проверяется прямо сервером Look; BOT_API_URL не нужен.
4. Проверить на реальном аккаунте: подписка в боте видна в миниаппе, новая
   подписка из миниаппа видна в боте, отметки эпизодов сохраняются после открытия.
   Прогресс просмотра не меняет `last_episode_id`, которым пользуются уведомления.

Уведомления продолжает отправлять существующий Python-бот с его расписанием.
Пауза в Look — папка просмотра, а не отключение уведомлений бота.
Ручное изменение каталожных сезонов не поддерживается новым сервером;
основной сценарий — добавление сериалов через поиск TVmaze.

## Статус

SQL-миграция применена. Production приложения развёрнут из коммита `a905336`.
Серверная проверка входа с токеном `@wellook_bot` и чтения девяти существующих
подписок прошла; анонимный запрос библиотеки возвращает 401.
Окончательная проверка открытия внутри Telegram выполняется пользователем.

Целевой Telegram-бот — только `@wellook_bot`. Vercel-проект `look-notify`
обслуживает интерфейс, а проект с техническим названием `scvrdio` — команды
и уведомления этого же бота. Оба используют токен `@wellook_bot` и прежнюю базу.
Адрес приложения: https://look-notify.vercel.app.
Старую основную ветку `main` пока не публиковать повторно: актуальный исходный
код находится в `codex/look-original-backend`.

Расписание проверки эпизодов в бэкенде: `0 9 * * *` (ежедневно 09:00 UTC).
Подписки не пересоздавались, курсоры уведомлений не сбрасывались.

Webhook `@wellook_bot` установлен на `https://scvrdio.vercel.app/api/telegram`
с новым секретом. Настроены команды и постоянная кнопка миниаппки, включая
индивидуальное меню владельца. Тест `/start` через обработчик завершился HTTP 200
и отправил меню владельцу. Проверены HTTP 200 с секретом и 401 без секрета.
Предыдущий секрет webhook больше не принимается; старый `@scvrdiobot` не является
точкой входа. Его регистрация webhook в Telegram не удалялась (старый токен
не извлекался); обработчик отклоняет старые запросы.
